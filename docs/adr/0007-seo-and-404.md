# 0007 — SEO, share images and a bilingual 404, all generated at build time

**Date:** 2026-11-04 · **Status:** Accepted

## Context
A static site can still be found, previewed and shared well — or not. GitHub Pages serves one
`404.html` for every missing path, and link previews (WhatsApp, LinkedIn) need a real PNG.

## Decision
- `robots.ts` and `sitemap.ts` (Next metadata routes, `force-static`). The sitemap lists every
  page in both languages with `hreflang` alternates and `x-default`.
- Every page has a `canonical` URL, `hreflang` alternates, Open Graph and Twitter card tags, and
  the home layout embeds `Organization` structured data (schema.org JSON-LD).
- Share image per language at `/<locale>/og.png`, rendered at build time by a static route
  handler with `next/og` and the Geist font files. A route handler instead of the
  `opengraph-image` convention so the exported file has a `.png` extension — GitHub Pages picks
  the content type from it.
- `global-not-found.tsx` (Next `experimental.globalNotFound`) renders a full, branded 404 in
  Portuguese and English, since the 404 can't know the visitor's language.

## Consequences
- `verify-build` fails if robots, sitemap or share images are missing, if a sitemap URL has no
  page, or if `404.html` is the framework default. E2E checks the 404 (status, content,
  accessibility), every sitemap URL, canonical, the share image content type and the JSON-LD.
- `experimental.globalNotFound` is an experimental flag; if Next changes it, the build or the
  404 checks fail loudly instead of silently shipping the default page.
